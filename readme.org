* org-roam-gt

Org-roam is a powerful knowledge management system, but its defaults
favour simplicity over scale.  As your node count grows into the thousands,
~org-roam-node-find~ slows noticeably, the standard capture targets are limited to files and nodes — you cannot
route a capture directly into a named heading or a computed destination such
as today's daily note — and frequent operations like refile and capture have
no built-in keyboard shortcuts.

~org-roam-gt~ addresses all of these — the first, second and fourth
through a single minor mode, and the third through a command that needs
no mode at all:

1. *Faster node display* — replaces the string-based display template with a
   function, which is significantly faster on large databases and lets you
   control formatting in Lisp rather than a custom mini-language.

2. *Richer capture targets* — six new ~:target~ forms for
   ~org-roam-capture-templates~ that let you route captures to computed nodes,
   named headings, arbitrary outline paths, and datetree entries.  These cover
   the patterns that come up constantly in a structured PKM workflow: "today's
   daily note, under the Log section", "a specific project node, under
   Actions", "a fixed reference file, two levels deep", "a journal entry
   under today's date".  Two capture-template extensions complement the new
   targets: ~(file "PATH")~ loads a template body from a file, and
   ~:create-file yes/no~ makes the template's intent about file creation
   explicit and enforced.  The up-front "Node:" prompt that upstream
   ~org-roam-capture~ always shows is skipped — templates that target a
   fixed node never prompt at all, and those that need one prompt only
   after you've picked the template.  A fix for an upstream org-roam bug
   that mis-placed plain templates positioned at a heading is also
   installed.

3. *Refile to those same targets* — ~org-roam-gt-refile~ accepts a
   ~:target~ in capture-template syntax, so a subtree can be moved into a
   named heading, an outline path or a datetree entry of a node.
   ~org-roam-refile~ reaches only the top of a node.

4. *Speed command menu* — a ~transient~ prefix bound to ~m~ in
   ~org-speed-commands~, giving one-keystroke access to capture, refile,
   find, and extract-subtree from any org heading.

** Installation

Once accepted by [[https://melpa.org/][MELPA]]:

#+begin_src emacs-lisp
(use-package org-roam-gt
  :ensure t
  :config
  ;; Optional: load the speed-command menu (transient is bundled with Emacs)
  (require 'org-roam-gt-transient)
  (org-roam-gt-mode 1))
#+end_src

Or from a local checkout:

#+begin_src emacs-lisp
(use-package org-roam-gt
  :load-path "~/.emacs.d/modules/org-roam-gt"
  :config
  (require 'org-roam-gt-transient)
  (org-roam-gt-mode 1))
#+end_src

To disable, call ~(org-roam-gt-mode -1)~.  All features are controlled
by the mode and restore their previous state on disable.

The menu uses ~transient~, which is bundled with Emacs — nothing extra
to install.  Just ~(require 'org-roam-gt-transient)~ before enabling
the mode.

** Selectively disabling features

Every feature is enabled by default.  Each can be turned off
independently before enabling the mode:

| Variable                                        | Turns off                              |
|-------------------------------------------------+----------------------------------------|
| ~org-roam-gt-enable-node-display-function~       | the faster node display function       |
| ~org-roam-gt-enable-capture-targets~             | the extended capture targets           |
| ~org-roam-gt-enable-path-canonicalization~       | collapsing symlink aliases             |
| ~org-roam-gt-inherit-roam-exclude~               | inherited ROAM_EXCLUDE                 |
| ~org-roam-gt-refresh-keyword-properties-on-index~ | re-reading =#+PROPERTY:= before indexing |
| ~org-roam-gt-check-duplicate-node-ids~           | refusing to index a repeated node ID   |
| ~org-roam-gt-track-directory-operations~         | following directory renames and deletions |

#+begin_src emacs-lisp
;; Keep org-roam's default display template
(setq org-roam-gt-enable-node-display-function nil)

;; Keep org-roam's capture targets
(setq org-roam-gt-enable-capture-targets nil)

(org-roam-gt-mode 1)
#+end_src

If the mode is already running, disable it, change the variable, then
re-enable:

#+begin_src emacs-lisp
(org-roam-gt-mode -1)
(setq org-roam-gt-enable-node-display-function nil)
(org-roam-gt-mode 1)
#+end_src

*** Speed command menu (opt-in)

The speed command menu is self-contained in ~org-roam-gt-transient.el~.
It uses ~org-roam-gt-enable-hook~ and ~org-roam-gt-disable-hook~ to
register and de-register itself with the mode.

To enable the menu, require it /before/ enabling the mode:

#+begin_src emacs-lisp
(require 'org-roam-gt-transient)   ; registers menu on the hooks
(org-roam-gt-mode 1)               ; fires org-roam-gt-enable-hook, installs menu
#+end_src

To disable the menu entirely, simply do not load
~org-roam-gt-transient.el~ — the menu key (~m~) will not be installed.

If you want to remove the menu after the mode is already running:

#+begin_src emacs-lisp
(remove-hook 'org-roam-gt-enable-hook  #'org-roam-gt-transient--enable)
(remove-hook 'org-roam-gt-disable-hook #'org-roam-gt-transient--disable)
(org-roam-gt-transient--disable)   ; clean up the current session
#+end_src

*** Hook-based extension API

~org-roam-gt-mode~ exposes two hooks for extensions that want to activate and
deactivate together with the mode:

| Hook                      | Fired when                          |
|---------------------------+-------------------------------------|
| ~org-roam-gt-enable-hook~   | Mode is being enabled (~:global t~)   |
| ~org-roam-gt-disable-hook~  | Mode is being disabled              |

Add your own functions to register custom behaviour:

#+begin_src emacs-lisp
(defun my-roam-ext--enable () ...)
(defun my-roam-ext--disable () ...)
(add-hook 'org-roam-gt-enable-hook  #'my-roam-ext--enable)
(add-hook 'org-roam-gt-disable-hook #'my-roam-ext--disable)
#+end_src

** New capture target types

The six new target types work alongside all existing ones.  Your current
templates need no changes — you simply add new templates that use the new
target types.

*Standard org-roam target types* (always available):

| Target type       | Description                                              |
|-------------------+----------------------------------------------------------|
| ~file~              | Capture to a specific file                               |
| ~file+head~         | Capture to a file; create it with a header if new        |
| ~file+olp~          | Capture to a specific outline path within a file         |
| ~file+head+olp~     | Combination of ~file+head~ and ~file+olp~                    |
| ~file+datetree~     | Capture into a date-tree within a file                   |
| ~node~              | Always prompts the user to find or create a node         |

The limitation of ~node~ is that it always prompts — you cannot point it at a
fixed destination or a computed one.  The new target types address this:

*New target types added by ~org-roam-gt-mode~*:

| Target type              | Destination node          | Position within node              |
|--------------------------+---------------------------+-----------------------------------|
| ~node~                     | Fixed ID/title, or prompt | Node entry point                  |
| ~nodefunc~                 | Returned by a function    | Node entry point                  |
| ~nodefunc+headline~        | Returned by a function    | Named heading (created if absent) |
| ~node+headline~            | Fixed ID/title, or prompt | Named heading (created if absent) |
| ~node+olp~                 | Fixed ID/title, or prompt | Outline path (created if absent)  |
| ~node+olp+datetree~        | Fixed ID/title, or prompt | Datetree entry under optional OLP |
| ~nodefunc+olp+datetree~    | Returned by a function    | Datetree entry under optional OLP |

*** =(node TITLE-OR-ID)=

The standard ~node~ target always prompts, even when you know the destination
in advance.  With ~org-roam-gt-mode~, passing a string goes directly to that
node by ID or title without prompting.  Passing ~nil~ still prompts, just as
the standard ~node~ does.

#+begin_src emacs-lisp
;; Go directly to a specific node — no prompt
'("f" "Farrington tip" entry
  "** %?\n"
  :target (node "mike-farrington-tips")
  :unnarrowed t)

;; Prompt the user to pick any node
'("n" "Note" plain
  "%?"
  :target (node nil)
  :unnarrowed t)
#+end_src

*** =(nodefunc FUNCTION)=

FUNCTION is called with no arguments and must return an ~org-roam-node~.
Capture is positioned at the node's entry point.

Use this when the destination node is computed at capture time — for
example, today's daily note.

#+begin_src emacs-lisp
'("+" "Daily log" plain
  "*** PROGRESS %?\n\n%a\n"
  :target (nodefunc my-daily-node-function)
  :unnarrowed t)
#+end_src

*** =(nodefunc+headline FUNCTION HEADLINE)=

Like ~nodefunc~, but positions inside a named heading within the node.
The heading is created as a child if it does not exist.

#+begin_src emacs-lisp
'("+" "Daily log" plain
  "*** PROGRESS %?\n\n%a\n"
  :target (nodefunc+headline my-daily-node-function "Log")
  :unnarrowed t)
#+end_src

*** =(node+headline TITLE-OR-ID HEADLINE)=

Looks up a node by its ID or title, then positions inside a named heading.
The heading is created as a child if absent.

If TITLE-OR-ID is ~nil~, the user is prompted to choose a node interactively.

#+begin_src emacs-lisp
;; Fixed destination node, fixed heading
'("c" "Cooking recipe" entry
  "** SOMEDAY %?\n\n%(my-web-link)\n\n"
  :target (node+headline "area-cooking-20240921-012344" "Recipes")
  :unnarrowed t)

;; User picks the node, fixed heading
'("T" "Todo" entry
  "** TODO %?\n%T\n\n%i\n"
  :target (node+headline nil "Actions")
  :unnarrowed t)

;; Prompt is narrowed by :filter-fn to nodes whose TODO keyword is PROJ or AREA
'("E" "Email under a project" entry
  "** TODO %?\n"
  :target (node+headline nil "Emails")
  :filter-fn (lambda (n) (member (org-roam-node-todo n) '("PROJ" "AREA")))
  :unnarrowed t)
#+end_src

The standard org-capture template property ~:filter-fn~ works with every
prompting target (~node~ nil, ~node+headline~ nil, ~node+olp~ nil,
~node+olp+datetree~ nil).  It receives an ~org-roam-node~ and returns
non-nil to keep it in the candidate pool.

*** =(node+olp TITLE-OR-ID "h1" "h2" ...)=

Like ~node+headline~ but navigates (or creates) an arbitrary outline path.
Each heading in the path is found or created in sequence.

If TITLE-OR-ID is ~nil~, the user is prompted interactively.
Heading strings may contain ~${var}~ template variables.

#+begin_src emacs-lisp
'("x" "Example" entry
  "** %?\n"
  :target (node+olp "my-node-id" "Section" "Subsection")
  :unnarrowed t)
#+end_src

*** =(node+olp+datetree TITLE-OR-ID "h1" "h2" ...)=

Positions capture at an org datetree entry beneath the node.  The OLP
headings are optional: pass none to build the datetree directly under the
node, or pass one or more to navigate (or create) intermediate headings
first.

The datetree is built by ~org-datetree-find-*-create~ per the ~:tree-type~
template property (default ~day~; other values: ~week~, ~month~, a list
grouping like ~(year month day)~, or a function that returns such a list).
Setting ~:time-prompt t~ asks for the date interactively; otherwise the
current date is used (respecting ~org-overriding-default-time~).

#+begin_src emacs-lisp
;; Daily log entry under Journal / YYYY / YYYY-MM / YYYY-MM-DD
'("j" "Journal" plain
  "- %U %?"
  :target (node+olp+datetree "my-journal-id" "Log")
  :unnarrowed t)

;; Weekly retrospective, ask for date at capture time
'("r" "Weekly retro" entry
  "** %?\n"
  :target (node+olp+datetree "my-journal-id")
  :tree-type week
  :time-prompt t
  :unnarrowed t)
#+end_src

*** =(nodefunc+olp+datetree FUNCTION "h1" "h2" ...)=

Like ~node+olp+datetree~, but the destination node is computed by
FUNCTION at capture time instead of looked up by ID or title.  All other
semantics (optional OLP, ~:tree-type~, ~:time-prompt~) are identical.

#+begin_src emacs-lisp
'("d" "Daily note" plain
  "- %?"
  :target (nodefunc+olp+datetree my-daily-node-function "Log")
  :unnarrowed t)
#+end_src

** Template body loaded from a file

Anywhere a template body (or the head string of ~file+head~ /
~file+head+olp~) is expected, ~(file "PATH")~ substitutes the contents
of PATH.  Relative paths are resolved against ~org-roam-directory~;
absolute paths pass through.  A missing file raises a user error at
capture time.

The file's contents are subject to the same ~${var}~ template
expansion as an inline body — put ~${title}~ or ~${slug}~ inside the
file and they are filled at capture time.

#+begin_src emacs-lisp
'("P" "New project file" plain
  "%?"
  :target (file+head "%<%Y%m%d%H%M%S>-${slug}.org"
                     (file "templates/project.txt"))
  :unnarrowed t)
#+end_src

Where ~templates/project.txt~ lives under ~org-roam-directory~ and
looks like:

#+begin_example
:PROPERTIES:
:ID: ${slug}
:END:
#+title: ${title}
#+filetags: :project:
#+end_example

** =:create-file= guard

An optional template property that asserts the template's intent about
file creation.  Only two values are legal; any other value is rejected
at capture time.

| Value  | Rule                                                              |
|--------+-------------------------------------------------------------------|
| ~yes~   | Destination file must *not* already exist; abort if it does.      |
| ~no~    | Destination file must already exist; abort if it does not.        |
| unset | No constraint (default org-roam behaviour).                       |

Applies to any target where a destination file can be identified —
file* targets before dispatch, node* targets after the node has been
resolved.  For node targets that always land on an existing node
(e.g. ~node~, ~node+headline~, ~node+olp~ with a known ID), the file
already exists, so ~no~ is trivially satisfied and ~yes~ always
errors.  Meaningful primarily on file* targets and on ~nodefunc*~
templates whose function may return a not-yet-existent node.

#+begin_src emacs-lisp
;; This template must create a fresh file each time
'("P" "New project" plain "%?"
  :target (file+head "${slug}.org" (file "templates/project.txt"))
  :create-file yes
  :unnarrowed t)

;; This template must land in an already-existing file
'("l" "Log entry" plain "- %U %?"
  :target (node+headline "my-daily-id" "Log")
  :create-file no
  :unnarrowed t)
#+end_src

** Refiling to a capture target

~org-roam-refile~ can only move a subtree to the top of a node.  A
capture template can say ~(node+headline nil "Actions")~ and land inside
it.  ~org-roam-gt-refile~ closes that gap: it takes a ~:target~ in the
same syntax as ~org-roam-capture-templates~ and refiles the subtree at
point there.

#+begin_src emacs-lisp
(org-roam-gt-refile :target '(node+headline nil "Actions")
                    :filter-fn #'my-project-p)
#+end_src

That prompts for a node — restricted to projects by the filter — and
moves the subtree under that node's "Actions" heading, creating the
heading if the node does not have one.  The destination is the same one
the matching capture template would have used.

Keyword arguments:

| Keyword      | Meaning                                                        |
|--------------+----------------------------------------------------------------|
| ~:target~      | Destination, in ~:target~ syntax.  Defaults to ~(node nil)~         |
| ~:node~        | Destination node, for targets that would otherwise prompt       |
| ~:filter-fn~   | Narrows the node prompt, as in ~org-roam-node-find~               |
| ~:visit~       | When non-nil, leave point at the destination                    |

Only the node-based target types can be refiled to: ~node~, ~nodefunc~,
~node+headline~, ~nodefunc+headline~, ~node+olp~, ~node+olp+datetree~ and
~nodefunc+olp+datetree~.  The ~file~-based types describe where to create
a file, which is not a question a refile can answer; they raise a user
error.

The destination node is chosen in this order: a title or ID written into
the target, then ~:node~, then a prompt.  So a wrapper can pass the node
it already has and skip the prompt entirely:

#+begin_src emacs-lisp
(defun my-refile-to-inbox ()
  "Refile the subtree at point under the Inbox heading of my inbox node."
  (interactive)
  (org-roam-gt-refile :target '(node+headline "my-inbox-id" "Inbox")))
#+end_src

Creating a heading that was absent is reported on the echo area — for
both refile and capture — since it usually means a typo in a target or a
refile aimed at the wrong node.

After the move the destination file is saved, because org-roam updates
its database on save; an unsaved destination holds content the database
does not know about.

Unlike the capture extensions, this function installs no advice and works
whether or not ~org-roam-gt-mode~ is enabled.

** One path per file

org-roam follows symlinks deliberately — every backend of
~org-roam--list-files~ passes ~-L~ — and normalizes the result with
~expand-file-name~, which does not resolve them.  A symlink that leads
back into ~org-roam-directory~ therefore makes one file reachable under
two paths.  Both are indexed, both carry the same node ID, and the
second write of that ID is where duplicate-node errors come from.  The
failure is quiet: the file sweep reports no error, and only some files
break outright.

With ~org-roam-gt-mode~ enabled, each file gets one path, in both
directions:

- ~org-roam-list-files~ is filtered so aliases collapse onto the
  canonical path.  The result is always a subset of what the finder
  reported — a path that was not listed is never introduced.
- ~org-roam-db-update-file~ and ~org-roam-db-clear-file~ canonicalize
  their file argument, so visiting a file through an alias path and
  saving it records the canonical path rather than reintroducing the
  duplicate the sweep just removed.

The canonical path is the physical location when it lies inside
~org-roam-directory~.  When it lies outside — a link such as
=links/notes= pointing at a tree kept elsewhere — the in-tree path is
kept unchanged, since rewriting it would move the file out of org-roam's
scope.  Where neither applies, the choice is deterministic (shortest
path, then alphabetical), because an unstable choice would make org-roam
treat the file as moved on alternating syncs.

~M-x org-roam-gt-report-aliased-files~ lists what is being collapsed,
reading the file list with canonicalization disabled so the topology
stays visible:

#+begin_example
3511 files listed, 3326 distinct, 185 reachable by several paths

/roam/papers/lee2017understanding.org
    also as: /roam/proj/2026-oss-and-ai/dmg/papers/lee2017understanding.org
#+end_example

Set ~org-roam-gt-enable-path-canonicalization~ to nil to leave org-roam's
behaviour untouched.

** Directory renames and deletions

~org-roam-db-autosync-mode~ keeps the database current by advising
~rename-file~ and ~delete-file~, both of which act on one file.  A whole
directory reaches neither: the rename handler tests its arguments with
~org-roam-file-p~, which a directory fails, and a directory is removed by
~delete-directory~, which carries no advice at all.  Move or delete a
directory of notes and every file it held keeps its rows, naming a path
that no longer exists, until the next ~org-roam-db-sync~.

With ~org-roam-gt-mode~ enabled:

- Renaming a directory inside ~org-roam-directory~ clears the rows
  recorded under the old path and indexes the Org files found under the
  new one.  A directory moved out of the tree is only cleared: nothing
  outside ~org-roam-directory~ is indexed.
- Deleting a directory clears the rows of the files that are actually
  gone once the deletion returns, so a deletion that fails part way does
  not cost live rows.  Trashed files count as deleted — they are no
  longer in the tree.

Both operations are wrapped rather than followed, because the rows
recorded under a directory can only be read while it still exists.
Renaming a single file is left to org-roam's own advice, and a directory
outside ~org-roam-directory~ never reaches the database at all.

Set ~org-roam-gt-track-directory-operations~ to nil to leave org-roam's
behaviour untouched.

** Speed commands

When ~org-roam-gt-transient.el~ is loaded (see the opt-in section above),
the key ~m~ is added to ~org-speed-commands~.  It opens a ~transient~
prefix with shortcuts for common org-roam operations:

| Key | Action                         |
|-----+--------------------------------|
| ~c~   | Capture (~org-roam-capture~)     |
| ~f~   | Find node (~org-roam-node-find~) |
| ~r~   | Refile to a node               |
| ~x~   | Extract subtree                |

Speed commands are available when point is at the beginning of a heading.

** Faster node search

When you invoke ~org-roam-node-find~, Emacs has to build the list of every
node in your database before you can start typing.  On a large database this
pause is long enough to interrupt your flow.  The delay comes from how each
node's display line is constructed: org-roam uses a format string with
~%~-placeholders, and assembling that string for every node on every
invocation is slow.

~org-roam-gt~ replaces the format string with a plain Lisp function that
produces the same display but runs faster, which shortens the pause
noticeably.  The completion interface looks and behaves identically.  The
original template is restored if you disable the mode.

** Development

The repository ships a ~Makefile~ that drives every dev workflow via a
project-local ~.elpa/~ (nothing touches your user package directory):

#+begin_src sh
make              # byte-compile
make test         # run the buttercup test suite
make lint         # package-lint
make checkdoc     # checkdoc (errors on any warning)
make check-declare  # verify declare-function arguments
make check        # compile + lint + checkdoc + check-declare
make clean        # remove *.elc
#+end_src

The GitHub Actions workflow at ~.github/workflows/package-lint.yml~
runs ~make lint~, ~make checkdoc~, ~make check-declare~, and ~make test~
on Emacs 30.1, 31.1, and snapshot.
